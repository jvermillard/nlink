# Upgrading from 0.31.0 to 0.32.0

0.32.0 carries the redesigns nlink-lab asked for in #534, which 0.31.0
left for their own cycle: namespace handles, the error model, ownership
and recreate in `NetworkConfig`, declarative traffic control, the
plan/apply split, and the nftables model. This guide grows with the
cycle: each breaking change adds its section when it lands.

## Compile breaks

### `Error::SequenceMismatch` and `Error::NamespaceRestoreFailed` are gone (#532)

Nothing constructed either variant: the sequence filter skips a stale
frame instead of failing, and namespace sockets have been made on a
thread of their own, which never needs restoring, since #185.
`Error::is_namespace_restore_failed()` goes with them. Remove any match
arm or call that names them; there is nothing to replace them with.

### `full` no longer includes `lab` (#532)

`lab` is test code: `LabNamespace`, `require_root!` and its siblings, and
a `tracing-subscriber` dependency. A crate that enabled `full` and used
any of those adds `lab`. Use it in `[dev-dependencies]` if only tests
need it:

```toml
[dev-dependencies]
nlink = { version = "0.32", features = ["lab"] }
```

### nlink no longer turns on tokio's `full` (#532)

The workspace asked tokio for `full`, so every crate depending on nlink
got it. nlink now asks for what it uses: `rt`, `net`, `sync`, `time` and
`macros`. A binary that relied on nlink for tokio features, such as
`rt-multi-thread` for `#[tokio::main]` or `signal`, names them in its own
tokio dependency.

### `LinkRecreate::blocked_by` is `Vec<Blocker>` (#513)

What would block a recreate was a list of strings; it is a list of
`config::Blocker`, an enum with one variant per kind of thing (`Address`,
`Route`, `Qdisc`, `Class`, `Filter`, `Fdb`, `Neighbour`, `ProxyNeighbour`,
`Nexthop`, `StackedLink`, `Port`, `ForeignNetnsPeer`, `Unsupported`). Each
one's `Display` is the string the list used to hold, so code that printed
them is unchanged:

```rust
// before
let text = recreate.blocked_by.join(", ");
// after
let text: Vec<String> = recreate.blocked_by.iter().map(ToString::to_string).collect();
if recreate.blocked_by.iter().any(|b| matches!(b, Blocker::Fdb { .. })) { /* … */ }
```

In JSON a blocker is an object tagged by `kind`:
`{"kind": "address", "dev": "v1", "address": "10.0.0.9", "prefix-len": 24}`.

### `ApplyResult` is `#[non_exhaustive]` and has `recreated` (#513)

It lists the links the apply deleted and created again, each a
`LinkRecreate` with its reason and its new `resets` (what the link lost:
an alias, a MAC address the kernel picked again). Build an `ApplyResult`
with `Default` and field assignment, not a struct literal.

### `RouteProtocol` has an `Other(u8)` variant (#512)

A protocol number nlink has no name for used to read back as `Unspec`, so
a route installed by `bird` with its own number, or by a config with
`NetworkConfig::route_protocol`, could not be told apart. `From<u8>` now
returns `RouteProtocol::Other(n)` for it. The enum has a variant with a
field, so `as u8` no longer compiles:

```rust
// before
let n = protocol as u8;
// after
let n = protocol.number(); // or u8::from(protocol)
```

`Display` prints a named protocol's name and an `Other`'s number, as
`ip route` does.

### `NetemConfig` is `#[non_exhaustive]` (#515)

It gained `ecn`, `slot`, `seed`, `distribution` and the three rate
overheads, and will gain more. A struct literal no longer compiles outside
nlink:

```rust
// before
let cfg = NetemConfig { delay: Some(d), ..Default::default() };
// after
let cfg = NetemConfig::new().delay(d);
```

Note that `new()` sets `limit` to 1000, tc(8)'s default, where
`..Default::default()` left it at 0.

### `FqPieOptions::ecn_prob_permille` is `ecn_prob_percent` (#631)

The kernel reports fq_pie's ECN probability as a whole percentage, and the
field always held that value. Its name said per-mille, and `ecn_prob()`
divided by 10, so the default of 10 % read as 1 %. Rename the field. Any
code that divided it by 10 itself should stop. `FqPieConfig::ecn_prob`
now refuses a fractional percentage.

### One `LinkStats` and one `LinkRates` (#525)

The crate had two of each. The `stats` module's are now the only ones:

- `nlink::netlink::stats::LinkStats` is the message-level `LinkStats`.
  Its counters are accessor methods, not fields. The link's name has
  moved to the snapshot:

  ```rust
  // before
  let bytes = snapshot.links[&ifindex].rx_bytes;
  let name = snapshot.links[&ifindex].name.clone();
  // after
  let bytes = snapshot.links[&ifindex].rx_bytes();
  let name = snapshot.names.get(&ifindex).cloned();
  ```

- `nlink::LinkRates` and `diagnostics::LinkRates` are now
  `stats::LinkRates`. Its fields are `f64` per second:

  | before | after |
  |---|---|
  | `rx_pps`, `tx_pps` | `rx_packets_per_sec`, `tx_packets_per_sec` |
  | `total_pps()` | `total_packets_per_sec()` |
  | `sample_duration_ms` | gone; the interval is between the two samples |
  | `rx_bps()` etc. as `u64` | `f64` |

  `stats::LinkRates` has no `name` field, and `between` no longer compares
  names. `StatsSnapshot::rates` and `RateSampler` do that comparison.
- `StatsSnapshot::rates(&previous, duration)` is now `rates(&previous)`.
  The interval is the time between the snapshots' `taken_at`.
  `StatsSnapshot` is `#[non_exhaustive]`; build one with `new()`, a
  `from_*` constructor, or `capture`.

### TC setters take typed units (#515)

Byte quantities take `Bytes`, and `PoliceAction` takes `Rate`:

```rust
// before
RedConfig::new().limit(100 * 1024).min(30 * 1024).max(90 * 1024);
BfifoConfig::new().limit(65536);
FqCodelConfig::new().memory_limit(32 << 20);
conn.plug_set_limit("eth0", parent, 10_000).await?;
PoliceAction::new().rate(1_250_000).burst(102_400);
PoliceAction::new().rate_bps(10_000_000);
// after
use nlink::{Bytes, Rate};
RedConfig::new().limit(Bytes::kib(100)).min(Bytes::kib(30)).max(Bytes::kib(90));
BfifoConfig::new().limit(Bytes::new(65536));
FqCodelConfig::new().memory_limit(Bytes::mib(32));
conn.plug_set_limit("eth0", parent, Bytes::new(10_000)).await?;
PoliceAction::new().rate(Rate::mbit(10)).burst(Bytes::kib(100));
PoliceAction::new().rate(Rate::mbit(10));
```

The setters affected are `GredConfig::limit`, `PlugConfig::limit`,
`PoliceAction::{peakrate, avrate, mtu}`, and those shown above. Packet
limits stay `u32`.

### `QdiscConfig::default_handle` returns `Option<TcHandle>` (#515)

It returned `Option<u32>`, and no code read it. A `QdiscConfig` you
implement yourself that overrides it should return a `TcHandle`.

### Filter protocols and priorities are typed (#515)

The filter methods, the builders' `.protocol()`/`.priority()` and
`FilterConfig` take `EthProto` and `FilterPriority` instead of `u16`:

```rust
// before
conn.add_filter_full("eth0", parent, None, 0x0800, 100, filter).await?;
conn.del_filter("eth0", parent, 0x0003, 1).await?;
FlowerFilter::new().protocol(0x86DD).priority(10);
// after
use nlink::{EthProto, FilterPriority};
conn.add_filter_full("eth0", parent, None, EthProto::IP, FilterPriority::new(100), filter)
    .await?;
conn.del_filter("eth0", parent, EthProto::ALL, FilterPriority::new(1)).await?;
FlowerFilter::new().protocol(EthProto::IPV6).priority(FilterPriority::new(10));
```

What a dump reports is typed as well: `TcMessage::protocol()` returns an
`EthProto`, and `priority()` returns a `FilterPriority`. Both compare equal
to a `u16`. Use `.as_u16()` where a number is needed, and
`"ip".parse::<EthProto>()` for a name. `DEFAULT_FILTER_PROTOCOL` is an
`EthProto`.

### `DeclaredQdiscType` is `QdiscSpec`, which holds the configs (#515)

A declared qdisc now holds the imperative config. Read a field there,
and match on a tuple variant:

```rust
// before
if let DeclaredQdiscType::Netem { delay_us, loss_percent, .. } = q.qdisc_type() { /* … */ }
// after
if let QdiscSpec::Netem(netem) = q.qdisc_type() {
    let (delay, loss) = (netem.delay, netem.loss); // Option<Duration>, Percent
}
```

`QdiscBuilder` is unchanged, and `QdiscBuilder::spec(config)` takes a whole
config. `DeclaredQdiscType` is a deprecated alias of `QdiscSpec`.

**JSON/YAML.** Qdiscs are now written in human units, and the 0.31 field
names are still read:

| 0.31 | 0.32 |
|---|---|
| `"delay_us": 100000` | `"delay": "100ms"` |
| `"loss_percent": 1.5` | `"loss": "1.5%"` |
| `"rate_bps": 12500000` (bytes/s) | `"rate": "100mbit"` |
| `"burst_bytes": 32768` | `"burst": "32kib"` |
| `"target_us": 5000` | `"target": "5ms"` |
| `"perturb_secs": 10` | `"perturb": "10s"` |

These documents are now refused:
- one that sets a value both ways;
- one that misspells a field, which used to be ignored;
- one with a percentage outside 0–100;
- one with a rate without its unit.

A TBF without a limit now fails validation, and so fails `from_json_str`.

### One `ReconcileOptions` and one `ReconcileReport` (#532)

There were two unrelated types of each name. The recipes' types were at the
crate root; the nftables types were also borrowed by `NetworkConfig` and
`WireguardConfig`. Now there is one of each, in `nlink::reconcile`. Every
old path still names it.

```rust
use nlink::reconcile::{ReconcileOptions, ReconcileReport};

let opts = ReconcileOptions::new()     // 3 retries from 100 ms
    .with_max_retries(5)               // was `.max_retries(5)`
    .with_backoff(Duration::from_millis(50)) // was `.backoff(…)`
    .with_dry_run(true)                // now honoured by every layer
    .with_fallback_to_apply(true);     // a recipe's; the layers ignore it
let report = cfg.apply_reconcile(&conn, opts).await?;
let n = report.changes_made;           // was `change_count` in the layers
```

- The layers' report field `change_count` is now `changes_made`, the name
  the recipes used.
- A recipe's report now also carries `attempts`.
- The recipes retry `EBUSY`, `EAGAIN` and an interrupted dump, like the
  layers do. Each attempt dumps the tree again.

### `DiffOptions` is `PlanOptions`; `ApplyOptions` is a plan and an execution (#519)

```rust
// before
let diff = cfg.diff_with_options(&conn, DiffOptions::default().purge(true)).await?;
if opts.dry_run { /* … */ }
diff.apply(&conn, ApplyOptions::default()).await?;

// after
let diff = cfg.diff_with_options(&conn, PlanOptions::default().purge(true)).await?;
if opts.exec.dry_run { /* … */ }        // and opts.plan.purge, …
diff.apply(&conn, ExecOptions::default()).await?;
```

- `ApplyOptions` is `{ plan: PlanOptions, exec: ExecOptions }`.
  - Its `with_*` setters are unchanged.
  - Fields are read through `plan` (`purge`, `purge_tables`,
    `purge_address_devs`, `previous`, `recreate_policy`, `owned`) or
    `exec` (`dry_run`, `continue_on_error`, `verify`).
  - `diff_options()` is deprecated: read `plan`.
- `ConfigDiff::apply` takes `impl Into<ExecOptions>`, because a diff
  already holds its plan.
  - An `ApplyOptions` still converts.
  - `Default::default()` no longer infers; write `ExecOptions::default()`.
  - `verify` now works there too: the diff remembers its config and plan.
    Before, it was ignored, like the plan options are.
- `DiffOptions` is a deprecated alias of `PlanOptions`.

### `Stack` plans, then applies (#519)

`Stack::plan_in(ns, PlanOptions)` returns a `StackPlan`, and
`StackPlan::apply(ns, ExecOptions)` applies exactly that plan.
`Stack::apply*` are now plan + apply: one diff of every layer, where they
used to diff twice.

| 0.31 | 0.32 |
|---|---|
| `StackDiff` | `StackPlan` (deprecated alias) |
| `StackApplyReport` | `StackReport` (deprecated alias) |
| `stack.diff()`, `diff_in(ns)`, `diff_in_with(ns, o)`, … | `stack.plan(o)`, `plan_in(ns, o)` (the `diff*` methods are deprecated) |
| `report.nftables_change_count` | `report.nftables` |
| `report.dry_run: Option<StackDiff>` | `report.dry_run: bool`, and the plan in `report.planned` |
| `Stack { network, .. }` literal | `Stack::new().network(..)`; `Stack` is `#[non_exhaustive]` |

- `StackReport` also has `wireguard_devices_created` and `attempts`.
- `exec.verify` plans every layer again, and fails with the new
  `Error::StackNotConverged`. Its kind is `ErrorKind::NotConverged`.
- `Stack::apply_reconcile_in(ns, ReconcileOptions, ApplyOptions)` plans and
  applies again on a transient error, or on an nftables commit refused
  because the ruleset moved (`ERESTART`).
- `WireguardConfigDiff::apply(conn)` is new. `WireguardApplyResult` now
  serializes.

## Deprecations

- **`MirredAction::{redirect_by_index, mirror_by_index,
  ingress_redirect_by_index, ingress_mirror_by_index}`** are replaced by
  `redirect_to_egress`, `mirror_to_egress`, `redirect_to_ingress` and
  `mirror_to_ingress` (#515). To redirect to an IFB, use
  `redirect_to_egress`.
- **`Connection::get_timeout()` → `operation_timeout()`** (#532), the name
  without the `get_` prefix the rest of the API does not use.
- **`namespace_events` (`NamespaceEventSubscriber`,
  `NamespaceNetlinkEvent`)** (#532). It duplicates `NetworkEvent::NewNsId`
  and `NetworkEvent::DelNsId`:

  ```rust
  // before
  let mut sub = NamespaceEventSubscriber::new().await?;
  while let Some(ev) = sub.recv().await? { /* NamespaceNetlinkEvent */ }

  // after
  let conn = Connection::<Route>::new()?;
  conn.subscribe(&[RtnetlinkGroup::NsId])?;
  let mut events = conn.events().await;
  while let Some(ev) = events.next().await {
      if let NetworkEvent::NewNsId(m) = ev? { /* m.nsid(), m.pid() */ }
  }
  ```

## Behaviour changes

- **A classful qdisc added at the root without a handle sits at `1:`
  (#515)**, instead of the kernel's `8001:`. This covers htb, prio, hfsc,
  drr, qfq, ets, multiq, mq, mqprio, taprio, atm and dsmark. Code that
  then named `8001:` should name `1:`, or pass the handle it wants.
- **`PerHostLimiter::remove` and `PerPeerImpairer::clear` leave a root
  they didn't build (#515).** A user's qdisc, or the other recipe's tree,
  is no longer deleted. `PerHostLimiter::remove` returns errors it used
  to swallow.

- **`NetworkConfig::validate()` refuses more (#518)**, and a diff runs it
  first. Before, each of these failed mid-apply, after the links before
  it were created, or never converged:
  - a kind setter called on another kind;
  - a VNI past 24 bits;
  - an IPv4 route with host bits;
  - table 0;
  - a cycle of masters;
  - a VLAN declared up on a lower device declared down;
  - a MAC on an ovpn or L3 netkit link.

  A missing parent or master is reported in `ConfigDiff::links_missing`,
  and the apply refuses it.
- **A second context stacks (#526).** `with_context` on a kernel error
  that has one already reads `"outer: inner"` in its `Display`; the outer
  one used to be dropped.
- **The diffs' `Display` has no trailing newline (#532).**
  `WireguardConfigDiff`'s had one; `ConfigDiff`'s and `NftablesDiff`'s
  did not. Print them with `println!`.
- **A declared prio qdisc sits at `1:` (#514)**, as HTB already did, so
  its classes and filters can name it. One the kernel had put at an
  automatic handle (`8001:`) is replaced once, on the first apply after
  the upgrade. Declare `.handle(..)` to keep another.
- **Netem percentages are rounded, as tc rounds them (#633).** nlink now
  puts the same probability in the kernel as tc(8): 1 % is 42949673, not
  42949672. A netem installed by an older nlink is one unit off, so a
  `PerPeerImpairer` or `NetworkConfig` reconcile replaces it once, on the
  first run after the upgrade. Some values, 1.2 % among them, used to be
  replaced on every run, and now converge.
- **fq_pie's `ecn_prob` is sent as a percentage (#631).** A config that
  asked for 20 % used to install 200 %, and now installs 20 %.
- **cake sends what tc sends (#635).**
  - `CakeConfig::new()` has `split_gso` on, the kernel's default. It was
    off, and was never sent, so it made no difference. `.split_gso(false)`
    and `no-split-gso` now turn splitting off.
  - The `nat`, `wash`, `ingress` and autorate flags are sent off as well
    as on, so a replace turns off one that was on.
  - An `rtt` with no `target` brings a target of a twentieth of the RTT,
    as tc's `rtt` does.
- **`SfqConfig::new()` leaves sfq's limit to the kernel (#637).** The
  `limit` field defaults to 0 instead of 127. The kernel's limit is still
  127, but a default sfq now has 128 flows rather than 127, the same as
  tc's. Code that read `cfg.limit` expecting 127 gets 0.
- **`StatsTracker` measures between snapshots, not calls (#525).** A
  rate is over the time between the two snapshots' `taken_at`.
  `DiagnosticReport::timestamp` is when the link counters were read, the
  end of the link dump, not the start of the scan.
- **An undeclared sfq `perturb` is the kernel's 0 (#515).** It is
  compared like any field. A declared sfq on a device whose sfq perturbs
  is replaced once, unless the declaration sets the period.
- **MSRV is 1.88** (#532). It was 1.98, the fleet toolchain the project
  builds with, which still builds it.
